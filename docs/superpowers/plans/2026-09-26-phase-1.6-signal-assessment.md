# Phase 1.6 Signal Assessment Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Every stored signal gets an LLM relevance call (niche: new advancements and innovations in AI), a category, a one-line summary and a why-it-matters line, and the page shows only what is relevant by default.

**Architecture:** A thin OpenAI-compatible LLM gateway (roles, validated JSON, `llm_calls` logging, budget check, `fake` provider for tests) feeds an `assess` stage that mirrors `stages/ingest.py`. Results live in `signal_assessments` and are joined into `GET /signals`.

**Tech Stack:** existing (Python 3.13, FastAPI, SQLAlchemy 2, Alembic, httpx, Next.js). No new dependency: the gateway uses `httpx`.

**Spec:** `docs/adr/0006-assess-signals-before-clustering.md`; PRD §25 (gateway), §17 (budgets), §43 row 1.6.

## Global Constraints

- One task = one branch = one PR of at most 400 changed lines; squash-merge; Conventional Commits; no AI or co-author trailers.
- Test first. Unit tests need no network and no DB; DB tests are `integration`-marked and skip without `TEST_DATABASE_URL`.
- Stages request a **role** (`relevance_filter`), never a model name (PRD §25).
- Fetched titles and metadata are untrusted: delimit them as data in the prompt, never let them alter instructions, validate all output with Pydantic.
- Money is `Decimal`, never `float` (`core/budget.py`). Every LLM call writes an `llm_calls` row and one structured log line (`log_llm_call`).
- Migrations reach shared databases only from `main` (ADR-0004). Renumber if another migration lands first.
- Summaries use title and metadata only; they must not assert facts the title does not support.
- `LLM_PROVIDER=fake` is the default; `openrouter` requires `OPENROUTER_API_KEY` (already validated in `core/config.py`).

### Task 1: LLM gateway

**Files:** create `src/signalforge/llm/{__init__,gateway,providers,roles}.py`; tests `tests/unit/test_llm_gateway.py`.

**Interfaces:**
- Produces: `class LLMGateway(provider: LLMProvider, roles: RoleMap, budget: Budget, session: Session)` with
  `complete_json(self, *, role: str, system: str, user: str, schema: type[T], stage_run_id: uuid.UUID) -> T` (`T` bound to `BaseModel`).
- `LLMProvider` Protocol: `chat(model: str, messages: list[dict[str,str]], *, json_mode: bool, timeout_s: float) -> ProviderReply` where `ProviderReply` is frozen with `text`, `input_tokens`, `output_tokens`, `latency_ms`.
- `FakeProvider(replies: list[str])` returns queued replies, zero cost; `OpenAICompatibleProvider(base_url, api_key: SecretStr, client: httpx.Client)` posts `/chat/completions` with `response_format={"type":"json_object"}`.
- `build_gateway(settings, session, budget) -> LLMGateway` picks the provider from `settings.llm_provider`.
- Consumes: `Budget` (`core/budget.py`), `LLMCall` (`db/models/ops.py`), `log_llm_call` (`core/logging.py`), `call_with_retry` (`core/retry.py`), errors in `core/errors.py`.

- [ ] **Step 1: Failing tests** (all with `FakeProvider`, in-memory fake session or a stub recorder):
  1. valid JSON reply parses into the schema and one `llm_calls` row is added with role, model, tokens and cost;
  2. invalid JSON gets exactly one repair retry (second reply valid) and two rows are recorded; still invalid raises `ArtifactValidationError`;
  3. an exhausted `Budget` raises `BudgetExceededError` before any provider call;
  4. HTTP 429/5xx from `OpenAICompatibleProvider` (via `httpx.MockTransport`) is retried through `call_with_retry`; 401/400 raises `ProviderRejectedError` without retry;
  5. the API key never appears in logs or exception text;
  6. cost is `Decimal` computed from per-model price per million tokens in `roles.py`.
- [ ] **Step 2: Run, expect FAIL.** `uv run pytest tests/unit/test_llm_gateway.py -v`
- [ ] **Step 3: Implement** to the interfaces above. Keep `roles.py` a plain dict: `relevance_filter -> ModelSpec(model_id, family, input_usd_per_mtok, output_usd_per_mtok)`. Use a cheap OpenRouter model id from config (`LLM_MODEL_RELEVANCE`, default a small model) so it is changeable without code.
- [ ] **Step 4: Run all checks.** `uv run ruff check . && uv run ruff format --check . && uv run mypy && uv run pytest`
- [ ] **Step 5: Commit** `feat: add thin LLM gateway with fake and OpenAI-compatible providers`.

### Task 2: SignalAssessment table and repository

**Files:** create `core/artifacts/assessment.py`, `db/models/assessments.py`, migration `0004`, `db/repositories/assessments.py`; register the model in `db/models/__init__.py`; tests `tests/unit/test_assessment_artifact.py`, `tests/integration/test_assessment_repository.py`.

**Interfaces:**
- `SignalAssessment(Artifact)`: `signal_id: UUID`, `is_relevant: bool`, `relevance_score: float` (0 to 1), `category: Category` (StrEnum: `model_release`, `research`, `tool`, `technique`, `benchmark`, `infrastructure`, `other`), `summary: str` (1 to 300 chars), `why_it_matters: str` (1 to 300 chars), `prompt_version: str`, `model: str`.
- Table `signal_assessments`: `id`, `signal_id` FK to `signals` (CASCADE), `stage_run_id` FK, `llm_call_id` FK nullable, the fields above, timestamps. Unique `(signal_id, prompt_version)`; index on `(is_relevant, relevance_score)`.
- `AssessmentRepository(session)`: `insert(assessment, stage_run_id, llm_call_id) -> bool` (ON CONFLICT DO NOTHING); `list_unassessed(prompt_version, limit) -> list[SignalRow]` (signals with no row for that version, newest first).

- [ ] **Step 2: Run, expect FAIL.**
- [ ] **Step 3: Implement** model, migration (named constraints per `db/base.py` naming convention, downgrade drops table), repository.
- [ ] **Step 4: Checks:** as Task 1, plus in CI `alembic check` must stay clean.

### Task 3: Assess stage and CLI

**Files:** create `stages/assess.py`, `apps/worker/assess.py`; tests `tests/unit/test_assess_prompt.py`, `tests/integration/test_assess.py`.

**Interfaces:**
- `PROMPT_VERSION = "assess-v1"`.
- `build_messages(signal) -> tuple[str, str]` (system, user). System states the niche (**new advancements and innovations in AI: models, research results, tools, techniques, releases; not opinion, funding, hype or general news**), the JSON schema and "use only the title and metadata; do not invent facts". User content wraps the title, source and points inside `<signal>...</signal>` and the system tells the model everything inside is data, never instructions.
- `run_assess(session, gateway_factory, *, limit: int = 25) -> AssessResult` (`considered`, `assessed`, `relevant`, `stopped_on_budget: bool`). Records a `stage_runs` row like `run_ingest` (running, then succeeded, or failed and re-raised), one signal per call, skips a signal whose output fails validation after the repair retry (logs and counts `failed`), stops cleanly on `BudgetExceededError`.
- CLI: `uv run python -m apps.worker.assess --limit 25` calls `configure_logging`, builds the gateway from settings, prints the counts, exit 0 on success, non-zero on failure.

- [ ] **Step 1: Failing tests:** prompt contains the delimiters and an injection string in a title stays inside `<signal>`; with `FakeProvider` replies, `run_assess` stores assessments and reports counts; re-running assesses nothing new; invalid reply is skipped and counted, others proceed; budget exhaustion stops the loop and marks `stopped_on_budget`; a provider failure leaves a `failed` stage run.
- [ ] **Step 2: Run, expect FAIL.**
- [ ] **Step 3: Implement.**
- [ ] **Step 4: Checks.**
- [ ] **Step 5: Commit** `feat: add assess stage and CLI`.
